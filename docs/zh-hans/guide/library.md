# 游戏库与游戏

## 添加游戏

**手动添加**:"Add Game"(添加游戏)按钮接受一个标题和一个可执行文件路径(或者一个启动器 URI,
例如 `steam://run/<appid>` —— 参见[下文](#uri-launches-vs-direct-executables))。适用于任何
来源插件尚未覆盖的情况。

**通过来源插件添加**:安装并启用一个来源插件后(Settings(设置) → Source(来源)),Settings
中会有一个 "Scan Now"(立即扫描)按钮,用于查找该插件已知的每一款游戏并将其添加到你的游戏库中。
之后再次运行扫描会检测新安装的游戏,而不会让已在游戏库中的游戏重复出现(参见下方的去重说明)。

## 编辑游戏

打开任意游戏的详情页(点击其封面/标题,或点击编辑图标)并切换到编辑模式。你可以覆盖标题、封面/
背景美术链接、描述(支持 Markdown)、发行日期和平台。"Fetch Metadata"(获取元数据)按钮会针对
当前标题重新运行你已启用的元数据提供方(Settings(设置) → Metadata Provider(元数据提供方)),
并填入所找到的任何信息 —— 当自动获取遗漏了某些内容,或某个提供方的数据在你添加游戏后发生变化时
很有用。

## 标签与合集

- **标签(Tags)** 是自由形式的标记("Co-op"、"Backlog"、"Completed") —— 在 Tags 侧边栏标签页
  创建/重命名/删除,并在对应游戏的详情页中逐一分配。
- **合集(Collections)** 用于将一个系列/系列作品分组("最终幻想") —— 与标签是不同的概念,
  但管理方式相同,均在各自的侧边栏标签页中进行。

## 搜索、筛选与排序

搜索栏接受普通标题文本以及三种特殊标记,所有标记都可以在同一次查询中组合使用:
`platform:steam`、`tag:coop`、`collection:"final fantasy"`(包含空格的值请加引号)。
输入 `platform:steam zelda` 会仅在 Steam 游戏范围内按标题搜索 "zelda"。

搜索栏下方,可点击的胶囊标签对应相同的平台/标签/合集 —— 点击某个胶囊标签会在搜索框中添加或移除对应的
标记,因此搜索栏与胶囊标签始终保持一致。同类的多个胶囊标签可以用 **OR**(匹配任一已选值 —— 默认方式)
或 **AND**(必须匹配所有已选值)方式组合;可以通过 "browse all filters"(浏览全部筛选项)胶囊标签
切换某个分类所使用的组合方式(这一行的显示数量有上限,该胶囊标签会打开一个弹窗,按平台/标签/合集分组
列出全部内容,不受数量限制)。未通过来源插件手动添加、因而没有平台信息的游戏,会显示在 `manual`
平台胶囊标签下。

视图模式切换按钮旁边有一个独立的排序下拉菜单,提供标题(A-Z)、最近玩过、玩得最多和最近添加等选项 ——
与网格/列表视图模式一样,你的选择会在重启后保留。

## 批量操作

点击排序下拉菜单旁的复选框式开关以进入选择模式:每张卡片/每一行都变成可单击选择的目标,并显示一个小型
复选框徽标,标明当前的选中状态。此时会出现一个 "已选择 N 项" 的栏,提供全选(会考虑当前生效的筛选/搜索
条件)和清除按钮,以及批量操作:添加标签、添加到合集,或将所选内容整体从游戏库中移除。点击 X 按钮退出
选择模式,返回正常浏览。

## 跨来源去重 {#deduplication-across-sources}

如果同一款游戏既被手动添加,又之后被某个来源插件的扫描发现(或被两个不同的来源插件同时发现),
Concourse 会将它们合并为一个条目,而不是显示重复项 —— 匹配依据是标题。当有多个来源发现了同一个
标题时,在你的 Source(来源)标签页优先级顺序中排位更靠后的插件将决定启动路径/平台(如果想让
另一个插件优先,可在那里重新排序插件)。

如果你确实希望两个同名条目保持独立(例如同一款游戏的两个不同版本),某个游戏的编辑表单中有一个
"Keep separate from plugin scans"(与插件扫描结果保持分离)复选框(`skip_dedup`) —— 勾选它可将
该特定条目排除在合并逻辑之外。

## 离线翻译 {#offline-translation}

游戏的标题和描述可以完全离线翻译成你当前的界面语言 —— 不使用任何外部翻译服务,任何数据都不会
离开你的设备。在某个游戏的详情页,"Translate"(翻译)按钮会打开一个包含三组选项的菜单(可滚动
或使用方向键在各组之间移动):

- **Translate(翻译)** —— 仅翻译标题、仅翻译描述,或两者都翻译。使用不同的所选模型重新运行会
  覆盖该字段之前的翻译。
- **Show(显示)** —— 在译文和原文之间切换,可按字段单独切换,也可一起切换。此选择会按游戏
  单独记住,因此之后再次打开某个游戏时,会显示你上次为该游戏所选的具体选项。
- **Remove(移除)** —— 清除某个字段(或两者)的缓存译文,恢复为原文且不留任何缓存内容。

**一次性设置**(在 Settings 中):先下载一次翻译引擎(体积较小的一次性下载),然后从下拉列表中
选择一个模型并下载。提供了几档模型规模,在体积/内存占用与质量之间做权衡 —— 全部在 CPU 上运行,
因此较小的档位翻译更快,在游戏运行期间与之并存时占用的内存也更少。其中有一档未经审查,专为翻译
NSFW 游戏自身的描述而设计,以免带安全调校的模型拒绝翻译合法的第三方文本。

缓存的译文与制作时所用的界面语言绑定 —— 切换界面语言,或编辑游戏的原始标题/描述,都会自动使其
失效(需要重新翻译才能为新语言或修改后的文本生成新的译文)。

## URI 启动方式与直接可执行文件方式 {#uri-launches-vs-direct-executables}

某些来源插件(Steam、Epic)通过平台 URI(`steam://run/...`、`com.epicgames.launcher://...`)
而非直接的 `.exe` 路径来启动游戏,因为这是该平台自身期望被告知启动游戏的方式。这类游戏的时长
追踪方式有所不同 —— 详见下方的[游戏时长追踪](#playtime-tracking)。

## 游戏时长追踪 {#playtime-tracking}

对于直接的可执行文件路径,Concourse 会等待实际进程,并在其退出后记录一次真实的会话
(开始/结束/时长)。对于通过 URI 启动的游戏,没有同样方式可等待的进程句柄,因此会话不会以同样
方式被记录 —— Stats(统计)标签页上的 "Recently Played"(最近玩过)/总时长数字,反映的是每种
启动方式实际可追踪到的内容。
