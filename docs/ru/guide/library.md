# Библиотека и игры

## Добавление игр

**Вручную**: кнопка "Add Game" принимает название и путь к исполняемому файлу (или URI лаунчера
вроде `steam://run/<appid>` - см. [ниже](#uri-launches-vs-direct-executables)). Используйте это
для всего, что ещё не покрыто плагином источника.

**Через плагин источника**: как только вы установили и включили плагин источника (Settings →
Source), в Settings появляется кнопка "Scan Now", которая находит каждую известную этому плагину
игру и добавляет их в вашу библиотеку. Повторный запуск сканирования позже подхватывает
новоустановленные игры, не дублируя уже имеющиеся в вашей библиотеке (см. дедупликацию ниже).

## Редактирование игры

Откройте страницу деталей любой игры (кликните по обложке/названию или по иконке Edit) и
переключитесь в режим редактирования. Вы можете переопределить название, URL-адреса
обложки/фонового арта, описание (поддерживается Markdown), дату выхода и платформу. Кнопка
"Fetch Metadata" повторно запускает ваши включённые поставщики метаданных (Settings → Metadata
Provider) по текущему названию и заполняет всё, что находит - полезно, если автоматическое
получение что-то пропустило, либо данные поставщика изменились с момента добавления игры.

## Теги и коллекции

- **Tags** - произвольные метки ("Co-op", "Backlog", "Completed") - создавайте/переименовывайте/
  удаляйте на вкладке боковой панели Tags, назначайте для отдельной игры на странице деталей этой
  игры.
- **Collections** группируют серию/франшизу ("Final Fantasy") - отдельное от тегов понятие,
  управляется так же, на собственной вкладке боковой панели.

## Поиск, фильтрация и сортировка

Строка поиска принимает обычный текст названия плюс три специальных токена, все из которых можно
комбинировать в одном запросе: `platform:steam`, `tag:coop`, `collection:"final fantasy"` (значение с
пробелами берите в кавычки). Ввод `platform:steam zelda` ищет "zelda" в названиях только среди игр Steam.

Под строкой поиска кликабельные плашки отражают те же платформы/теги/коллекции - клик по одной добавляет
или убирает её токен из строки поиска, так что строка поиска и плашки всегда согласованы друг с другом.
Несколько плашек одного вида комбинируются либо через **OR** (совпадает любое выбранное значение - по
умолчанию), либо через **AND** (должно совпадать каждое выбранное значение); переключить, какой режим
использует категория, можно через плашку "browse all filters" (строка ограничена по количеству, а эта
плашка открывает модальное окно со всем списком без ограничений, сгруппированным по
платформам/тегам/коллекциям). Игра, добавленная вручную без платформы от плагина источника, отображается
под плашкой платформы `manual`.

Отдельный выпадающий список сортировки рядом с переключателем режима отображения предлагает Название (А-Я),
Недавно игралось, Больше всего наиграно и Недавно добавлено - ваш выбор сохраняется между перезапусками,
как и режим отображения сеткой/списком.

## Пакетные операции

Нажмите на переключатель в виде флажка рядом с выпадающим списком сортировки, чтобы войти в режим выбора:
каждая карточка/строка становится целью для выбора одним кликом, с небольшим значком-флажком, показывающим
текущий выбор. Появляется панель "Выбрано: N" с кнопками Выбрать все (учитывает текущий активный
фильтр/поиск) и Очистить, а также пакетные действия: добавить тег, добавить в коллекцию или удалить весь
выбор из вашей библиотеки. Выйдите из режима выбора кнопкой X, чтобы вернуться к обычному просмотру.

## Дедупликация между источниками {#deduplication-across-sources}

Если одна и та же игра одновременно добавлена вручную и позже найдена сканированием плагина
источника (или найдена двумя разными плагинами источников), Concourse объединяет их в одну
запись, а не показывает дубликаты - сопоставление по названию. Когда одно и то же название нашли
несколько источников, побеждает плагин, который стоит позже в порядке приоритета на вкладке
Source, - именно его путь запуска/платформа используются (переставьте плагины там, если хотите,
чтобы приоритет был у другого).

Если вам действительно нужно, чтобы две записи с одинаковым названием оставались раздельными
(например, две разные версии одной и той же игры), в форме редактирования игры есть флажок "Keep
separate from plugin scans" (`skip_dedup`) - отметьте его, чтобы исключить эту конкретную запись
из логики объединения.

## Офлайн-перевод {#offline-translation}

Название и описание игры можно перевести на текущий язык интерфейса полностью офлайн - без
внешнего сервиса перевода, ничего не покидает вашу машину. На странице деталей игры кнопка
"Translate" открывает меню с тремя группами (прокручивайте или используйте стрелки для перехода
между ними):

- **Translate** - перевести только название, только описание или оба сразу. Повторный запуск с
  другой выбранной моделью перезаписывает предыдущий перевод для этого поля.
- **Show** - переключение между переведённым и оригинальным текстом, для отдельного поля или для
  обоих сразу. Этот выбор запоминается для каждой игры отдельно, так что при повторном открытии
  игры позже будет показано то, что вы выбрали для неё в последний раз.
- **Remove** - очищает кэшированный перевод для поля (или для обоих), возвращая оригинал без
  какого-либо оставшегося кэша.

**Однократная настройка** (Settings): скачайте движок перевода один раз (небольшая, одноразовая
загрузка), затем выберите модель из выпадающего списка и скачайте её тоже. Предлагается
несколько уровней моделей, компромисс между размером/ОЗУ и качеством - все работают полностью на
CPU, поэтому модель меньшего уровня переводит быстрее и использует меньше памяти, пока рядом с
ней работает игра. Один уровень без цензуры, предназначен для перевода собственных описаний
NSFW-игр без отказа модели с настройкой безопасности переводить легитимный сторонний текст.

Кэшированный перевод привязан к языку интерфейса, для которого он был сделан, - смена языка
интерфейса или редактирование оригинального названия/описания игры автоматически делает его
недействительным (переведите заново, чтобы получить свежий перевод для нового языка или
изменённого текста).

## Запуск через URI против прямых исполняемых файлов {#uri-launches-vs-direct-executables}

Некоторые плагины источников (Steam, Epic) запускают игру через URI платформы
(`steam://run/...`, `com.epicgames.launcher://...`), а не через прямой путь к `.exe`, поскольку
именно так сама платформа ожидает команду на запуск игры. Отслеживание времени игры работает для
них иначе - см. [Отслеживание времени игры](#playtime-tracking) ниже.

## Отслеживание времени игры {#playtime-tracking}

Для прямого пути к исполняемому файлу Concourse ожидает завершения реального процесса и
записывает настоящую сессию (начало/конец/длительность) после его выхода. Для игры, запущенной
через URI, нет дескриптора процесса, который можно было бы ожидать таким же образом, поэтому
сессия не записывается таким же образом - показатели "Recently Played"/общих часов на вкладке
Stats отражают то, что фактически отслеживаемо для каждого метода запуска.
