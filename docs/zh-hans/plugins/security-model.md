# 安全模型

通过 URL 安装 WASM 插件,运行的仍然是你并未编写的任意代码 —— 这与运行任何下载来的 `.exe` 面临
的现实风险相同。Concourse 并不假装仅凭 WASM 沙盒就能解决这个问题;本页说明的是它实际做了什么,
以及没有做什么。

## wasmtime 沙盒本身

每个 WASM 插件都运行在一个 [wasmtime](https://wasmtime.dev/) Component Model 实例中,默认没有
对任何东西的环境访问权限 —— 没有文件系统、没有网络、没有进程生成,什么都没有,除非某个特定的
`host` 函数授予了它。这是基线:一个插件只能做 `host` 接口所暴露的事情(参见
[WIT 接口](./wit-interface)),永远无法超出这个范围,无论插件自身代码试图做什么。

## 路径限定范围 {#path-scoping}

`plugin-dir()`(`<app data>/wasm-plugins/<kind>/<plugin-id>/`)始终隐式可读写 —— 每个插件都
免费获得一个私有沙盒目录。超出此范围的任何访问都需要满足以下之一:

- **一个已声明的静态范围** —— 插件在某个已知位置确实需要的固定注册表配置单元+键前缀,或固定的
  文件系统路径前缀(例如某个平台固定的厂商注册表键,或一个固定的 manifest 目录)。声明一次,
  宿主会在每次文件/注册表调用时进行检查。
- **一个运行时申请的范围**(`request-read-scope`) —— 用于只能在运行时才能发现的目录(例如用户
  的 Steam 安装实际把游戏库文件夹放在哪里)。宿主只有在同时识别出该插件 id *并且* 所申请的路径
  通过针对该厂商的真实结构检查(例如要求存在一个 `steamapps` 子目录)时才会授予此权限 —— 一个
  未被识别的插件 id 会被直接拒绝,绝不会被默默信任。

无论哪种方式,插件在 manifest 中声明的(或在安装确认时展示的)范围都会在用户安装它之前展示给
用户,因此"这个插件实际上能够触及我磁盘上的什么内容"在一开始就是可见的,而不仅仅是在后台被
默默强制执行。

## 进程生成门控

`spawn-process`/`run-and-wait` 被限定在一个明确的 `"run-programs"` 能力授权之后 —— 插件在其
manifest 的 `capabilities` 字段中声明此项,会在安装确认界面触发一条真实的"该插件会在你的系统上
运行其他程序"提示,用户必须主动同意。宿主无论 manifest 声明与否都会强制执行该门控(插件不能
仅靠省略该字段就跳过提示、同时仍然调用该函数) —— `capabilities` 字段只决定界面是否会请求该
授权。

## 网络限定范围

`http-get`/`http-request`/`download-bytes` 是按插件分别加入允许列表/限速的,而非一个笼统的
"可以访问整个互联网"的授权。

## 这*没有*解决的问题:信任问题,而非仅仅是沙盒问题

路径/进程/网络的范围限定,限制的是插件*能够触及什么*,但对代码本身在该范围内是否做了恶意的事情
则无能为力(一个来源插件确实需要 `spawn-process` 来启动游戏 —— 这不是沙盒能够区分于启动别的
什么东西的事情)。还有两层机制专门应对这一点:

### 代码签名(仅供参考)

已发布的插件版本可以携带 [Sigstore](https://www.sigstore.dev/) 认证 —— 可验证的证明,说明是
哪次 CI 构建、从哪个源码 commit 产生了某个具体的 `.wasm` 二进制文件。这**仅供参考,不是硬性的
安装时门控** —— Concourse 不会拒绝安装未签名的插件,因为那样同样会挡住尚未设置好签名流程的
插件作者。参考性审核信息会显示在安装确认界面中,而对于下方的精选注册表而言,这一层则*确实*被
硬性强制执行。

### 精选注册表(硬性门控)

[`concourse-plugin-registry`](https://github.com/smh0505/concourse-plugin-registry) 是一份
经过审核、带哈希固定的插件列表 —— 每个条目都将插件的 manifest/WASM 固定到一个确切的 commit
SHA 和内容哈希。通过注册表安装(而非自由粘贴 URL)在**哈希不匹配时会硬性拒绝** —— 如果实际
提供的内容不再与审核时的内容匹配,安装会直接失败,而不是发出警告后继续。将某个条目从注册表中
撤下,正是撤销机制本身(仅在安装时生效 —— 不会波及已经安装的副本)。

**简而言之**:通过注册表安装的插件获得真实的、强制执行的完整性保证。通过自由 URL 安装的插件
获得沙盒保护和可见的已声明范围,但实际的信任决定仍然在你自己手中 —— 如果你想让自己的插件获得
更强、经过审核的这一档保证,参见[发布](./publishing)。
