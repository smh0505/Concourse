# プラグインアーキテクチャ概要

Concourseは、単一のプラグインシステムを通じて多くのソースからゲームを1つのライブラリに集約し、自身を
再スキンします。プラグインには5つの種類があります。すべての種類が1つのマニフェスト形式とローダーを
共有しますが、それぞれの種類が実装する契約が異なります。

## 5つのプラグイン種別

| 種類 | 役割 | 選択方式 |
|---|---|---|
| `source` | プラットフォーム(Steam、GOG、Epicなど)をスキャンしてインストール済みのゲームを見つけ、起動する | 複数有効化 |
| `theme` | 色/フォント/カードのビジュアルを再スキンする | 排他(常に1つだけアクティブ) |
| `metadata` | 外部データベースからゲームの説明/リリース日/アートワークを取得する | 複数有効化 |
| `controller` | Big Pictureナビゲーション用に物理ゲームパッドのボタン/軸をマッピングする | 排他 |
| `wrapper` | プラグイン自身が管理する互換レイヤー(ロケールエミュレータなど)を通してゲームを起動する | 複数有効化 |

ソースプラグインとメタデータプロバイダプラグインは、それぞれ独立して**複数有効化**できます
(Settingsのチェックボックス) - 複数のソースプラグインと複数のメタデータプロバイダを同時に実行し、
それぞれが他にはないゲーム/フィールドを提供できます。テーマプラグインとコントローラーマッピング
プラグインは**排他的な単一選択**です(ラジオボタン) - 常に1つのスキンと1つの物理入力方式だけを
使用します。

## プラグインを提供する2つの方法

1. **WASMプラグイン** — 実行時にURL経由で(またはキュレーションされたレジストリ経由で)ダウンロードされる、
   独立してインストールされる`.wasm`コンポーネントで、サンドボックス化された
   [wasmtime](https://wasmtime.dev/) Component Modelインスタンス内で実行されます。これは今日の
   サードパーティ`source`/`wrapper`/`metadata`プラグインの実装経路です - [はじめに](./getting-started)と
   [WITインターフェース](./wit-interface)リファレンスを参照してください。
2. **データのみのテーママニフェスト** — `theme`プラグイン専用に、完全なWASMプラグイン機構を必要としない
   場合、マニフェストを純粋なJSON(`cssVariables`/`cardVisual`/`fontFaces`のみで、コードは一切なし)に
   できます。詳細は[テーママニフェスト](./theme-manifests)を参照してください。

WASMプラグインは、[WITワールド](https://component-model.bytecodealliance.org/design/wit.html)がこれまでに
定義されている3つの種類、`source`、`wrapper`、`metadata`にのみ存在します。今日サードパーティの`theme`
プラグインを構築するということは、上記のデータのみのマニフェスト経路を意味します。`controller`
マッピングプラグインには現時点でサードパーティの経路がありません - Concourseの組み込みゲームパッド
マッピングはアプリに直接コンパイルされており、新しいものを追加するには独立したプラグインを提供する
のではなくConcourse自体に貢献する必要があります。

## なぜネイティブコードやスクリプトではなくWASMなのか

Concourseはかつて、サードパーティプラグイン向けにダウンロード可能なネイティブ実行ファイルとスクリプト
言語を検討していました。両方とも同じ理由で却下されました: プラグインは自分の仕事(Steamインストールの
スキャン、ラッパーを通したゲームの起動)をこなすために実際のファイルシステム/レジストリ/ネットワーク/
プロセスアクセスを必要としますが、どちらの選択肢も*スコープされた*アクセスを付与できません -
ネイティブバイナリやサンドボックス化されていないスクリプトは、アプリ全体と同じ特権を得てしまいます。
Component Modelを介したWASMは代わりに真の能力ベースのサンドボックス化を実現します: プラグインは
ConcourseのRust側が実装し許可した場合にのみ`host`インターフェース関数を得ることができ、それでも
ほとんどの関数はさらにプラグインごとにスコープされます([セキュリティモデル](./security-model)参照)。
