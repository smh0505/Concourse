# 公開

## 自由形式のURLインストール(常に利用可能)

誰でも、どこにも掲載されることなく、今日あなたのプラグインをインストールできます - Concourseの
「Add Plugin」ダイアログは、`plugin.json`マニフェストへの直接URLを受け付けます。コンパイル済みの
`.wasm`とマニフェストをリリースアセットとして含めてGitHubリリースを公開し、マニフェストの
リリースアセットURLを共有すれば完了です。これは補助的な手段ではなく、本物のファーストクラスの
インストール経路です - プラグイン作者はインストール可能になるためにどのレジストリにも掲載される
必要はありません。

自由形式のURLに対してアップデートチェックがうまく機能するよう、通常の方法(タグ付きバージョン、
例えば`v0.2.0`)でリリースを公開し、`.../releases/latest/...`リンクではなくそのタグ自身のアセット
URLを人々に伝えてください。そうすることで、特定のインストールが実際にインストールされた時点の
ものに固定されたままになります。

### コード署名(推奨)

あなたのプラグインリポジトリのCIがリリース成果物のビルド来歴を証明している場合(例えば
[`actions/attest-build-provenance`](https://github.com/actions/attest-build-provenance))、
Concourseはそれをインストール確認UIで参考情報としての検証として表示します - ユーザーがインストール
しようとしている`.wasm`が改ざんされたコピーではなく本当にあなたのリポジトリ自身のCIから来たという
証拠です。これは必須ではありませんが、自由形式のURLインストールがレジストリエントリでは得られる
唯一のもの(レジストリエントリでなければ他に得られないもの)です([セキュリティモデル](./security-model)参照)。

## キュレーションされたレジストリ

[`concourse-plugin-registry`](https://github.com/smh0505/concourse-plugin-registry)は、
インストール時に厳格なコンテンツ検証を受ける、手動でキュレーションされたハッシュ固定リストです
(不一致は単にフラグを立てるのではなく完全に拒否されます) - 自由形式のURLインストールより意味のある
形で強力な保証です。正直なところ、この文書の執筆時点では、これはオープンなコミュニティによる
提出プロセスではなく、1人によってレビューされている(`smh0505`、Concourse自身と同じメンテナー)と
自ら文書化しています - 「レビュー済み」とは誰かが実際にその特定の固定バージョンのソースを読んだことを
意味し、そのポリシーを最初に変更しない限り、任意のサードパーティのプルリクエストを無条件に受け入れる
方式には対応していません。あなたのプラグインを掲載対象として検討してほしい場合は、自分のエントリを
追加するプルリクエストがそのまま承認されると想定するのではなく、そのリポジトリでissueを開いてください。

### 掲載が実際に固定するもの

```json
{
  "id": "your-plugin-id",
  "name": "Your Plugin",
  "kind": "source",
  "repo": "you/your-plugin-repo",
  "manifestUrl": "https://github.com/you/your-plugin-repo/releases/download/v0.2.0/plugin.json",
  "wasmSha256": "<sha256 of the pinned .wasm, computed by the reviewer>"
}
```

`manifestUrl`は常に`.../latest/...`ではなく、1つの特定の不変なリリースアセットを指します -
キュレーションされたエントリの要点全体は、今日インストールされるものがレビューされたものと正確に
一致することであり、次に何を公開しようとそれとは関係ないからです。`wasmSha256`は、レビューする人が
あなたの実際のリリース成果物から計算し、このレジストリ経由のすべてのインストールで実際にダウンロード
されたバイトと照合されます。

### 掲載を最新に保つ

あなたのプラグインが実際に掲載された場合、レジストリ自身のCIは(リリースワークフローが送信する
`repository_dispatch`経由で)あなたの新しいリリースを自動検出し、レジストリに対してバージョン更新の
プルリクエストを自動的に開くことができます - 誰かがアップデートを出荷したことに気づく必要なく、
再取得、再ハッシュ化、レビュー用の新しいリリースアセットの再固定を行います。そのプルリクエストは
それでも人間によるマージを必要とします。これは初回掲載と同じレビュー基準です。
