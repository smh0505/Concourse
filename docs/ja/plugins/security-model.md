# セキュリティモデル

WASMプラグインのURLインストールは、依然としてあなたが書いていない任意のコードを実行します -
これはダウンロードした`.exe`を実行するのと同じ現実のリスクです。ConcourseはWASMサンドボックスだけで
それが解決すると装ってはいません。このページでは、実際にそれについて何をしているか、そして何をしていないかを
説明します。

## wasmtimeサンドボックス自体

すべてのWASMプラグインは、特定の`host`関数がそれを許可しない限り、何にも周辺アクセスを持たない
[wasmtime](https://wasmtime.dev/) Component Modelインスタンス内で実行されます -
ファイルシステムも、ネットワークも、プロセス生成も、何もありません。これがベースラインです:
プラグインが実際にできることは、プラグイン自身のコードが何を試みようとも、`host`インターフェースが
公開するものだけで、それを超えることは決してありません([WITインターフェース](./wit-interface)参照)。

## パススコーピング {#path-scoping}

`plugin-dir()`(`<app data>/wasm-plugins/<kind>/<plugin-id>/`)は常に暗黙的に読み書き可能です -
すべてのプラグインは無料でプライベートなサンドボックスディレクトリを得ます。それを超えるものは
以下のいずれかが必要です。

- **宣言された静的スコープ** - プラグインが既知の場所で本当に必要とする固定のレジストリハイブ+キー
  プレフィックスまたはファイルシステムパスプレフィックス(例えばプラットフォームの固定ベンダー
  レジストリキーや固定マニフェストディレクトリ)。一度宣言され、ファイル/レジストリ呼び出しのたびに
  ホストによってチェックされます。
- **実行時にリクエストされるスコープ**(`request-read-scope`) - 実行時にのみ発見可能なディレクトリ
  向け(ユーザーの実際のSteamインストールがライブラリフォルダを実際に置いた場所など)。ホストは、
  プラグインidを認識し*かつ*リクエストされたパスがそのベンダーの実際の構造チェック(例えば
  `steamapps`サブディレクトリの存在を要求するなど)に合格した場合にのみこれを許可します -
  認識されないプラグインidは、暗黙的に信頼されることなく、無条件に拒否されます。

いずれにせよ、プラグインのマニフェストで宣言された(またはインストール確認で表示された)スコープは、
インストールする前にユーザーに表示されます。「これが実際にディスク上で何に触れられるか」は、
サイレントに強制されるだけでなく、事前に可視化されます。

## プロセス生成のゲート

`spawn-process`/`run-and-wait`は明示的な`"run-programs"`機能グラントの背後にゲートされています -
プラグインがそのマニフェストの`capabilities`フィールドでこれを宣言すると、インストール確認UIで
「このプラグインはあなたのシステム上で他のプログラムを実行します」という実際のプロンプトが表示され、
ユーザーはこれを積極的に承諾する必要があります。ホストはマニフェストが何を宣言していようとゲートを
強制します(プラグインは単にフィールドを省略してプロンプトをスキップし、それでも関数を呼び出すことは
できません) - `capabilities`フィールドは、UIがそもそもグラントを求めるかどうかだけを制御します。

## ネットワークスコーピング

`http-get`/`http-request`/`download-bytes`はプラグインごとにアローリスト化/レート制限されており、
「インターネット全体に到達できる」という包括的な許可ではありません。

## これが解決しない*こと*: サンドボックス化だけでなく信頼の問題

パス/プロセス/ネットワークのスコーピングは、プラグインが*到達できる範囲*を制限しますが、そのコード自身が
そのスコープ内で何か悪意のあることをするかどうかについては何も語りません(ソースプラグインはゲームを
起動するために本当に`spawn-process`を必要としますが、それが何か別のものを起動していないかをサンドボックス
が区別することはできません)。これに対処するためにさらに2つの層があります。

### コード署名(参考情報)

公開されたプラグインリリースは、[Sigstore](https://www.sigstore.dev/)による証明を持つことができます -
特定の`.wasm`バイナリをどのCIビルドが生成し、どのソースコミットから作られたかの検証可能な証拠です。
これは**参考情報であり、強制的なインストール時のゲートではありません** - Concourseは署名されていない
プラグインのインストールを拒否しません。それをすると、まだ署名を設定していないプラグイン作者を
同じくらい容易にブロックしてしまうためです。参考情報のレビューはインストール確認UIに表示され、
下記のキュレーションされたレジストリでは*厳格に*強制されます。

### キュレーションされたレジストリ(厳格にゲートされる)

[`concourse-plugin-registry`](https://github.com/smh0505/concourse-plugin-registry)は、レビュー済みで
ハッシュ固定されたプラグインのリストです - 各エントリはプラグインのマニフェスト/WASMを正確なコミット
SHAとコンテンツハッシュに固定します。レジストリ経由(自由形式で貼り付けられたURLではなく)でインストール
すると、**ハッシュ不一致で厳格に拒否されます** - 実際に配信されているものがレビューされたものと
もはや一致しない場合、警告して続行するのではなく、インストールが完全に失敗します。レジストリから
エントリを取り下げることが失効の仕組み(インストール時のみ - すでにインストールされているコピーには
遡って影響しません)です。

**要するに**: レジストリ経由でインストールされたプラグインは、実際に強制される整合性の保証を得られます。
自由形式のURLでインストールされたプラグインは、サンドボックス化と可視化された宣言済みスコープを得ますが、
実際の信頼の判断は依然としてあなた自身のものです - より強力な、レビュー済みの階層に自分のプラグインを
到達させたい場合は[公開](./publishing)を参照してください。
