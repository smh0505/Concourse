# Справочник манифеста

Каждый плагин - встроенный TypeScript, WASM или манифест темы только с данными - описывается
манифестом `plugin.json`. Эта страница документирует каждое поле, которое понимает загрузчик
Concourse (источник: интерфейс `PluginManifest` в `src/plugins/manifest.ts`).

## Основные поля (каждый плагин)

| Поле | Тип | Обязательно | Примечания |
|---|---|---|---|
| `id` | `string` | да | Уникальный идентификатор. Используется как имя директории установки для WASM-плагинов - держите его безопасным для файловой системы. |
| `name` | `string` | да | Отображаемое имя, показываемое в Settings. |
| `version` | `string` | да | Обычный SemVer, независимый от версии самого приложения. См. [версионирование](#versioning) ниже. |
| `kind` | `"source" \| "theme" \| "metadata" \| "controller" \| "wrapper"` | да | Какую возможность предоставляет этот плагин - определяет, что должен экспортировать его модуль/компонент точки входа. |
| `entry` | `string` | да | Путь к скомпилированному файлу `.wasm`, относительно собственной папки плагина. |
| `runtime` | `"wasm" \| "data"` | нет | Установите `"wasm"` для WASM-плагина или `"data"` для манифеста темы без кода (нет `entry` для загрузки вообще - `cssVariables` *и есть* весь плагин). Сторонний манифест всегда должен устанавливать одно из этих двух значений. (`"ts"`/отсутствие значения - третье значение, которое тоже распознаёт загрузчик, но оно означает модуль TypeScript времени сборки, встроенный в само приложение, - только для внутреннего использования, никогда не то, что стоит устанавливать в распространяемом манифесте.) |
| `installable` | `boolean` | нет | True, если этот плагин реализует жизненный цикл установки/удаления (`install()`/`uninstall()`/`isInstalled()`) - определяет, показывается ли автоматически общий UI кнопки "Install". |

Манифесты тем имеют собственный выделенный набор полей (`cssVariables`/`cardVisual`/
`fontFaces`) - см. [Манифесты тем](./theme-manifests), а не эту страницу, для них.

## Поля WASM-плагина

| Поле | Тип | Примечания |
|---|---|---|
| `settingsSchema` | массив `{ key, label, type? }` | Объявляет пользовательские настраиваемые параметры (например, API-ключ) - хост рендерит одну общую форму настроек на основе этого, вместо того чтобы вашему плагину нужен был собственный кастомный UI настроек. `type: "password"` маскирует ввод. |
| `capabilities` | `string[]` | Какие ограниченные возможности хоста фактически вызывает этот плагин. Сегодня только `"run-programs"` (ограничивает `spawn-process`/`run-and-wait`) - см. [Модель безопасности](./security-model). Хост применяет это ограничение независимо от того, что вы здесь объявите; это поле влияет только на то, запрашивает ли UI подтверждения установки явное разрешение у пользователя. |

`pathScopes`/`httpScopes` (объявленный доступ на чтение за пределами собственной директории
плагина и разрешённые сетевые хосты) отображаются в диалоге подтверждения установки для видимости
пользователю, но вычисляются хостом на основе фактических запросов вашего плагина на уровне WIT,
а не объявляются напрямую в `plugin.json` - см. [Модель безопасности](./security-model) о том,
как на самом деле работает ограничение области.

## Поля, добавляемые хостом (никогда не устанавливайте их сами)

| Поле | Тип | Примечания |
|---|---|---|
| `sourceUrl` | `string` | Точный URL, с которого это было установлено, - добавляется хостом во время установки, чтобы последующая проверка обновлений могла повторно получить и сравнить версии. |
| `installedViaRegistry` | `boolean` | True, если установлено через проверенный реестр с зафиксированным хэшем, а не через произвольно вставленный URL - меняет то, как работает проверка обновлений (зафиксированный реестром `sourceUrl` привязан к SHA коммита и заморожен навсегда; проверка на обновление означает повторное получение *текущей* записи реестра для этого id, а не повторное получение `sourceUrl` снова). |

## Пример: минимальный манифест плагина source

```json
{
  "id": "my-scanner-plugin",
  "name": "My Scanner Plugin",
  "version": "0.1.0",
  "kind": "source",
  "entry": "my_scanner_plugin.wasm"
}
```

См. [Манифесты тем](./theme-manifests) для примера манифеста темы.

## Версионирование {#versioning}

Версии плагинов - это обычный SemVer, отслеживаемый независимо от версии самого приложения:

- **Patch**: исправление бага, без изменения манифеста/поведения.
- **Minor**: новая возможность, обратно совместимая - по-прежнему работает с тем же
  WIT-интерфейсом хоста (WASM-плагины) или формой `PluginBase` (TS-плагины).
- **Major**: критическое изменение - меняется форма манифеста, или (для WASM-плагинов) плагину
  теперь требуется версия интерфейса `wit/plugin.wit`, которой нет у более старой сборки
  Concourse. Это сигнал "не устанавливайте это на более старой сборке приложения".

Отдельно устанавливаемые WASM-плагины и манифесты тем только с данными по традиции начинаются с
`0.1.0`/`1.0.0` соответственно - манифест темы только с содержимым достаточно стабилен, чтобы
начинаться с `1.0.0`, тогда как WASM-плагин с реальной логикой установки/запуска обычно начинается
с `0.1.0`, пока не будет проверен в реальном использовании.
