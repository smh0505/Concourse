*この翻訳は機械翻訳です(アプリ本体のUIロケールと同じ方式 - 下記の[Localization](#機能)参照)。
まだネイティブスピーカーによるレビューは行われていません。*

複数のソース(Steam、Epic、GOG、Xbox、EA app、Ubisoft Connect、手動登録、さらにプラグイン経由で
拡張可能)からゲームを集約し、
一つの統合ライブラリにまとめるデスクトップアプリです。コンソール風のコントローラー優先
「Big Picture」モードを備え、PlayniteやSteam自体のライブラリに近い雰囲気を持っています。

コアアプリは軽量に保たれています。基本ライブラリを超える機能(ソーススキャナー、テーマ、
メタデータプロバイダー、コントローラーマッピング、互換性ラッパー)はほぼすべてプラグインです。

## 機能

- **ライブラリコア** - 手動での「ゲームを追加」、SQLiteベースのストレージ、グリッド/リスト
  表示、タグ付け、検索/フィルタリング
- **メタデータとメディア** - SteamGridDBによるカバーアート、IGDBによる説明/ジャンル/発売日、
  手動上書き
- **起動とプレイ時間トラッキング** - ソースを問わない統一的な起動(直接exe、Steamの
  `steam://` URI、Epic/GOGのプロトコルハンドラー、互換性ラッパー経由で起動するゲーム)、
  ゲームの起動方法に応じたプロセス終了ベースまたはフォルダーベースのプレイ時間トラッキング
- **Big Pictureモード** - タイルグリッドとカバーフロー式スライドショー表示を備えた
  全画面ゲームパッドナビゲーションUI、背景アートのクロスフェード、起動時自動起動トグル
- **互換性ラッパー** - デフォルト以外のロケールが必要なゲーム向けのゲームごとの
  Locale Remulator / Locale Emulatorプロファイル
- **プラグインシステム** - 5種類のプラグイン(source、theme、metadata provider、
  controller mapping、compatibility wrapper)、ビルド時(`src/plugins/`配下にバンドルされた
  TypeScriptプラグイン)またはランタイム(ダウンロード可能なWebAssemblyプラグイン - 下記参照)
  のいずれかでロード
- **ローカライゼーション** - 10言語でUIを提供(英語+機械翻訳された9ロケール)、アプリ全体の
  再スキン用にテーマから設定可能な`--font-family`、コード不要のデータのみテーマ層
  (`cssVariables` + カバーアート領域用の任意の`cardVisual` JSON-ASTオーバーライド)
- **オフライン翻訳** - ゲームのタイトル/説明を、外部サービスを一切使わずに現在のUI言語へ
  完全にオンデバイスで翻訳(llama.cppの公式プリビルドサーバーバイナリを一度だけダウンロード
  し、モデルを選択(CPUに優しい複数の階層、NSFWゲームの説明向けの無検閲階層1つ)した後、
  ゲーム詳細ページからタイトルと本文を独立して翻訳/表示切替/取り消し可能)。翻訳はゲーム単位
  ・フィールド単位で保存され、ロケール切り替えや原文編集時に自動的に無効化されます
- **自動更新** - アプリ本体とインストール済みのすべてのプラグイン/テーマが自動的に更新を
  確認・適用

## 技術スタック

- **Tauri 2**(Rustバックエンド)+ **Vue 3**(`<script setup>`、TypeScript)フロントエンド
- **SQLite**(`tauri-plugin-sql`経由)、バージョン管理されたマイグレーションでスキーマを進化
- フロントエンド状態管理に**Pinia**、ドメインごとに1ストア
- ランタイムダウンロード可能なプラグインシステム用の**wasmtime**(Wasm Component Model)

## 開発

このリポジトリはnpm/yarn/pnpmではなく[`bun`](https://bun.sh)を使用します。

```sh
bun install          # JS依存関係のインストール
bun run dev           # Vite開発サーバーのみ(フロントエンド)
bunx tauri dev         # フルアプリ(フロントエンド+Rustバックエンド)、ホットリロード
bunx tauri build        # 本番デスクトップバイナリ
```

`src-tauri/`から: フルビルドなしでRustのコンパイルを素早く確認する`cargo check`。

## プラグインアーキテクチャ

すべてのプラグインは`plugin.json`マニフェスト(`{ id, name, version, kind, entry }`)を持ち、
`kind`に応じて5つのインターフェースのいずれかを実装します:

- `source` - ゲームソース連携向けの`scan()` / `launch()` / `getInstallStatus()`
  (複数同時有効化可能)
- `theme` - CSS変数(色、フォント、ボーダー/角丸)およびカバーアート領域向けの任意の
  JSON-AST `cardVisual`オーバーライド(単一有効化); `cssVariables`のみのマニフェストは
  コード不要。コンポーネントスロットオーバーライド(カスタムVueコンポーネント全体の差し替え)
  は初期にサポートされていましたが、このクローズドボキャブラリーAST階層に置き換えられ
  廃止されました - テーマが注入できるeval/実行コードパスは存在しません
- `metadata` - カバーアート/説明/ジャンルプロバイダー向けの`fetchMetadata(title)`
  (複数同時有効化可能)
- `controller` - 特定の物理コントローラーレイアウト向けの`GamepadMapping`(ボタン/軸
  インデックス)(単一有効化)
- `wrapper` - 独自のインストールを管理し、ロケールプロファイル経由で対象実行ファイルを
  起動する互換性ラッパー(Locale Remulator/Emulatorなど)

ビルド時プラグインは`src/plugins/<id>/`配下にあり、Viteの`import.meta.glob`経由で検出
されます。ランタイムプラグインはマニフェストURL(設定→該当タブ→プラグインを追加)から
インストールするか、アプリのデータディレクトリに手動でダウンロード/展開するWebAssembly
コンポーネント(`source`/`wrapper`/`metadata`種別)で、Rustバックエンドに組み込まれた
`wasmtime`ホスト経由でロードされます。データのみテーマ(`cssVariables`のみ、コードなし)は
WASMサンドボックスを一切必要としない、別のコード不要URLインストール階層です。

### 公式プラグイン

完全なリスト(リポジトリリンク、最新リリースのダウンロードリンク、インストール手順)は
ドキュメントサイトの
**[Official Plugins](https://smh0505.github.io/Concourse/guide/official-plugins)**を
参照してください。

**セキュリティに関する注記(Milestone 12、完了):** wasmtimeのComponent Modelサンドボックスは
メモリ安全性を保証し(プラグインはホストメモリを破損させたり、自身の実行範囲を逃れたりできない)、
実害を及ぼしうるプラグインに公開されているすべてのホスト関数は現在ゲーティングされています:
- `spawn-process`/`run-and-wait`には明示的で可視化された、プラグインごとの許可が必要です -
  プラグインはマニフェストで`capabilities: ["run-programs"]`を宣言する必要があり、実際に
  許可されるまでアプリはそのプラグインの代わりに何も実行しません(URLからのインストール時は
  インストール確認ダイアログのチェックボックス、既にインストール済みのプラグインの場合は
  設定内の「権限が必要」の行と付与ボタン)。
- `write-file`/`remove-dir`は例外なくプラグイン自身のディレクトリに厳格に閉じ込められます。
  `read-file`/`list-dir`/`path-exists`/レジストリアクセスはマニフェストで宣言された
  許可リスト(`pathScopes`)に加え、インストール場所を事前に把握できない唯一のプラグインで
  あるSteamについては検証済みのランタイムスコープリクエストの対象となります - ホストは
  アクセスを許可する前に実際の構造的シグネチャ(`steamapps`サブディレクトリ)を確認し、
  バリデーターを持たないプラグインIDは無条件で拒否します。
- `http-get`/`http-request`/`download-bytes`はマニフェストで宣言されたホスト名許可
  リスト(`httpScopes`)にスコープされます - プラグインは宣言したホスト(完全一致または
  サブドメイン)にのみアクセス可能で、任意の攻撃者が制御するURLにはアクセスできません。

それでも、完全に信頼できる提供元のプラグインのみをインストールしてください - これは
「プラグインがシステムやネットワークのどこにでも密かにアクセスできる」問題を解決するもので
あり、完全なアプリストア級の信頼モデルではありません。

**トラストモデル(Milestone 13、完了):** 相互に補完的で独立した2つの層です。
- **署名** - すべての公式プラグインリリースは
  [Sigstore](https://www.sigstore.dev/)のビルド来歴証明で署名されており、公開された
  `.wasm`をそれをビルドした正確なコミットとCI実行に紐付けます。Concourseはインストール時に
  これを確認し、結果を表示します - **あくまで参考情報であり、強制ゲートではありません。**
  これはアーティファクトが本当にそのリポジトリのCIから来ており、以降改ざんされていないことを
  確認します(改ざん、侵害されたリリーストークン、乗っ取られたリポジトリが不正なビルドを
  紛れ込ませるケースを検出)が、リポジトリ作者の意図を保証するものでは**ありません**。悪意の
  ある作者のコードも、自身のCIが実際にコミットした通りにビルド・署名すれば、完全に有効な
  署名を得られます。
- **キュレーションされたレジストリ** -
  [`concourse-plugin-registry`](https://github.com/smh0505/concourse-plugin-registry)、
  実際に内容を確認した固定バージョンのプラグインの手動管理リストで、各エントリは特定の
  リリースと実際のSHA256に固定されています。「プラグインを追加」ダイアログはフリー
  フォームのURLフィールドと並んでこれらを表示します。レジストリからのインストールは、
  署名の参考チェックとは異なり、ハッシュ不一致時に**強制拒否**されます - このハッシュは
  レビュー後に手作業で選ばれたものなので、不一致は「レビューされたものではない」という
  実際のシグナルです。レジストリからエントリを削除することは今後のインストールに対する
  取り消しになります(既にインストール済みのコピーには遡及適用されません)。フリーフォーム
  のURLインストールはいずれにせよ以前と同様に機能します - レジストリは必須のゲートでは
  なく、追加のより信頼できる経路です。

### サードパーティに関する告知

Concourse自体のソースはMITライセンスであり、リポジトリやビルド済みバイナリにサードパーティの
コンテンツはバンドルされていません。オフライン翻訳機能(Milestone 20)は、2種類のサード
パーティコンテンツを実行時にユーザーのマシンへ直接ダウンロードします。それぞれ独自の
別個の条項に従うものであり、Concourseがそれらを再配布しているわけではなく、透明性のために
ここに記載しています:

- **[llama.cpp](https://github.com/ggml-org/llama.cpp)**(MIT) - 翻訳エンジンそのもの。
  Concourseは公式のプリビルド済みWindowsリリースバイナリをGitHubからダウンロードし、
  サブプロセスとして実行します。llama.cppのコードはConcourseにコンパイル・同梱されません。
- **モデルの重み**は、設定画面でのユーザー自身の選択に基づきHugging Faceからダウンロード
  され、それぞれ各モデルカード自体のライセンスに従います - `qwen2.5-1.5b`/`qwen3-4b`/
  `gemma4-e2b`はすべてApache 2.0です(Gemma 4は2026年4月に特にApache 2.0へ移行し、
  以前のGemma世代が採用していたより制限的なライセンスを置き換えました)。2つの無検閲階層
  (`qwen3-4b-abliterated`、`gemma4-e2b-abliterated`)はそれぞれのベースモデルのライセンス
  を継承します。商用利用の前に、各モデル自体のHugging Faceモデルカードを必ずご確認ください。
