# Обзор архитектуры плагинов

Concourse объединяет игры из множества источников в одну библиотеку и переоформляет собственный
вид через единую систему плагинов с пятью видами. Каждый вид использует общий формат манифеста и
загрузчик; различается лишь контракт, который реализует плагин этого вида.

## Пять видов плагинов

| Вид | Задача | Выбор |
|---|---|---|
| `source` | Сканирует платформу (Steam, GOG, Epic, ...) на предмет установленных игр, запускает их | многократно включаемый |
| `theme` | Переоформляет цвета/шрифты/визуал карточек | эксклюзивный (один активен одновременно) |
| `metadata` | Получает описание/дату выхода/арт для игры из внешней базы данных | многократно включаемый |
| `controller` | Сопоставляет физические кнопки/оси геймпада для навигации в Big Picture | эксклюзивный |
| `wrapper` | Запускает игру через слой совместимости, которым сам управляет (например, локальный эмулятор) | многократно включаемый |

Плагины source и metadata-provider независимо **многократно включаемы** (флажки в Settings) - вы
можете одновременно запускать несколько плагинов источников и несколько поставщиков метаданных,
каждый из которых вносит игры/поля, которых нет у других. Плагины theme и controller-mapping -
**эксклюзивный единственный выбор** (радиокнопки) - вы всегда просматриваете один скин и одну
физическую схему ввода одновременно.

## Два способа поставки плагина

1. **WASM-плагин** - отдельно устанавливаемый компонент `.wasm`, скачиваемый по URL (или через
   проверенный реестр) во время выполнения, работающий в изолированном экземпляре Component
   Model [wasmtime](https://wasmtime.dev/). Это путь для сторонних плагинов
   `source`/`wrapper`/`metadata` сегодня - см. [Начало работы](./getting-started) и справочник
   [WIT-интерфейс](./wit-interface).
2. **Манифест темы, состоящий только из данных** - специально для плагинов `theme` манифест
   может быть чистым JSON (`cssVariables`/`cardVisual`/`fontFaces`, вообще без кода), если ему не
   нужна вся машинерия WASM-плагинов. См. [Манифесты тем](./theme-manifests).

WASM-плагины существуют только для трёх видов, для которых на данный момент определён
[WIT-мир](https://component-model.bytecodealliance.org/design/wit.html): `source`, `wrapper`,
`metadata`. Разработка стороннего плагина `theme` сегодня означает путь манифеста только с
данными, описанный выше. В настоящее время нет стороннего пути для плагинов раскладки
`controller` - встроенные раскладки геймпада Concourse скомпилированы прямо в приложение, и
добавление новой сегодня означает вклад в сам Concourse, а не поставку отдельного плагина.

## Почему WASM, а не нативный код или скриптинг

Concourse ранее рассматривал скачиваемые нативные исполняемые файлы и язык скриптов для сторонних
плагинов. Оба варианта были отклонены по одной и той же причине: плагину нужен реальный доступ к
файловой системе/реестру/сети/процессам, чтобы выполнять свою работу (сканирование установки
Steam, запуск игры через обёртку), а ни один из вариантов не может предоставить *ограниченный
(scoped)* доступ - нативный бинарник или несанкционированный (unsandboxed) скрипт получает те же
привилегии, что и всё приложение целиком. WASM через Component Model даёт вместо этого настоящую
песочницу на основе возможностей (capability-based sandboxing): плагин получает функцию
интерфейса `host` только если Rust-сторона Concourse её реализует и предоставляет, и даже тогда
большинство функций дополнительно ограничены по области действия для каждого плагина отдельно
(см. [Модель безопасности](./security-model)).
