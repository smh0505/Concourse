# Security Model

URL을 통한 WASM 플러그인 설치는 여전히 여러분이 작성하지 않은 임의의 코드를 실행합니다 -
다운로드한 `.exe`를 실행하는 것과 동일한 실제 위험입니다. Concourse는 WASM 샌드박스만으로 이
문제가 해결된다고 가정하지 않습니다. 이 페이지는 실제로 무엇을 하고 있고, 무엇을 하지 않는지를
설명합니다.

## wasmtime 샌드박스 자체

모든 WASM 플러그인은 [wasmtime](https://wasmtime.dev/) Component Model 인스턴스 안에서
실행되며, 특정 `host` 함수가 부여하지 않는 한 그 무엇에도 주변(ambient) 접근 권한이 없습니다 -
파일시스템도, 네트워크도, 프로세스 생성도, 아무것도 없습니다. 이것이 기준선입니다: 플러그인은
`host` 인터페이스가 노출하는 것만 할 수 있으며([WIT Interface](./wit-interface) 참고),
플러그인 코드가 무엇을 시도하든 그 이상은 절대 불가능합니다.

## 경로 범위 지정 {#path-scoping}

`plugin-dir()`(`<app data>/wasm-plugins/<kind>/<plugin-id>/`)은 항상 암묵적으로
읽기/쓰기 가능합니다 - 모든 플러그인은 무료로 자신만의 샌드박스 디렉터리를 받습니다. 그 이상은
다음 중 하나가 필요합니다:

- **선언된 정적 범위** - 플러그인이 알려진 위치에서 정말로 필요로 하는 고정된 레지스트리
  hive+key 접두사나 파일시스템 경로 접두사(예: 플랫폼의 고정 벤더 레지스트리 키, 또는 고정
  매니페스트 디렉터리). 한 번 선언되면 파일/레지스트리 호출마다 호스트가 검사합니다.
- **런타임에 요청된 범위**(`request-read-scope`) - 런타임에만 알 수 있는 디렉터리(사용자의
  실제 Steam 설치가 라이브러리 폴더를 실제로 어디에 두었는지)를 위한 것입니다. 호스트는
  플러그인 id를 인식하고 *동시에* 요청된 경로가 해당 벤더에 대한 실제 구조적 검사(예:
  `steamapps` 하위 디렉터리 요구)를 통과하는 경우에만 이를 부여합니다 - 인식되지 않는 플러그인
  id는 조용히 신뢰되지 않고 즉시 거부됩니다.

어느 쪽이든 플러그인의 매니페스트에 선언된(또는 설치 확인 시 표시되는) 범위는 설치 전에 사용자에게
보여지므로, "이것이 실제로 내 디스크에서 무엇을 건드릴 수 있는지"가 조용히 강제되는 것이 아니라
사전에 명시적으로 드러납니다.

## 프로세스 생성 게이트

`spawn-process`/`run-and-wait`는 명시적인 `"run-programs"` capability 부여 뒤에 게이팅되어
있습니다 - 플러그인이 매니페스트의 `capabilities` 필드에 이를 선언하면 설치 확인 UI에 "이
플러그인은 시스템의 다른 프로그램을 실행합니다"라는 실제 프롬프트가 표시되며, 사용자가 이를
적극적으로 수락해야 합니다. 매니페스트가 무엇을 선언하든 호스트는 게이트를 강제합니다(플러그인이
그저 필드를 생략해 프롬프트를 건너뛰고도 함수를 호출할 수는 없습니다) - `capabilities` 필드는
UI가 애초에 승인을 요청할지 여부만 제어합니다.

## 네트워크 범위 지정

`http-get`/`http-request`/`download-bytes`는 플러그인별로 허용 목록화/속도 제한되며, "인터넷
전체에 접근 가능"이라는 포괄적인 허용이 아닙니다.

## 이것이 해결하지 못하는 것: 샌드박싱이 아니라 신뢰의 문제

경로/프로세스/네트워크 범위 지정은 플러그인이 *도달할 수 있는 범위*를 제한하지만, 그 범위 안에서
코드 자체가 악의적인 행동을 하는지에 대해서는 아무것도 말해주지 않습니다(소스 플러그인은 게임을
실행하기 위해 정말로 `spawn-process`가 필요하며 - 그것이 다른 무언가를 실행하는 것과 다르다는
것을 샌드박스가 구분할 수는 없습니다). 이를 다루는 두 개의 추가 계층이 있습니다:

### 코드 서명 (권고 사항)

게시된 플러그인 릴리스는 [Sigstore](https://www.sigstore.dev/) 증명(attestation)을 포함할 수
있습니다 - 특정 `.wasm` 바이너리가 어느 CI 빌드에서, 어느 소스 커밋으로부터 만들어졌는지에
대한 검증 가능한 증거입니다. 이것은 **권고 사항일 뿐, 설치 시점의 강제 게이트가 아닙니다** -
Concourse는 서명되지 않은 플러그인 설치를 거부하지 않습니다. 그렇게 하면 아직 서명을 설정하지
않은 플러그인 작성자를 똑같이 막아버리기 때문입니다. 권고성 검토 결과는 설치 확인 UI에
표시되며, 아래의 큐레이션된 레지스트리에서는 *실제로* 강제됩니다.

### 큐레이션된 레지스트리 (강제 게이팅)

[`concourse-plugin-registry`](https://github.com/smh0505/concourse-plugin-registry)는 검토를
거치고 해시로 고정된 플러그인 목록입니다 - 각 항목은 플러그인의 매니페스트/WASM을 정확한 커밋
SHA와 콘텐츠 해시에 고정합니다. 자유 형식으로 붙여넣은 URL이 아니라 레지스트리를 통해 설치하면
**해시 불일치 시 강제로 거부됩니다** - 실제로 제공되는 것이 검토된 것과 더 이상 일치하지 않으면
경고 후 계속 진행하는 것이 아니라 설치 자체가 완전히 실패합니다. 레지스트리에서 항목을 내리는
것이 곧 폐기(revocation) 메커니즘입니다(설치 시점에만 적용되며, 이미 설치된 사본까지 소급되지는
않습니다).

**요약하면**: 레지스트리를 통해 설치한 플러그인은 실제로 강제되는 무결성 보장을 받습니다. 자유
형식 URL로 설치한 플러그인은 샌드박싱과 눈에 보이는 선언된 범위를 얻지만, 실제 신뢰 여부 판단은
여전히 여러분의 몫입니다 - 더 강력한 검토 등급에 도달하고 싶다면
[Publishing](./publishing)을 참고하세요.
