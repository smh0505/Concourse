# Модель безопасности

Установка по URL для WASM-плагина всё равно выполняет произвольный код, который вы не писали, -
тот же реальный риск, что и при запуске любого скачанного `.exe`. Concourse не делает вид, что
одна лишь WASM-песочница решает эту проблему; эта страница о том, что она на самом деле для этого
делает и чего не делает.

## Собственно песочница wasmtime

Каждый WASM-плагин работает внутри экземпляра Component Model
[wasmtime](https://wasmtime.dev/) без какого-либо окружающего доступа к чему-либо - ни файловой
системы, ни сети, ни запуска процессов, ничего, если это не предоставляет конкретная функция
`host`. Это базовый уровень: плагин может делать только то, что предоставляет интерфейс `host`
(см. [WIT-интерфейс](./wit-interface)), никогда ничего сверх этого, независимо от того, что
пытается сделать код самого плагина.

## Ограничение путей (Path scoping) {#path-scoping}

`plugin-dir()` (`<app data>/wasm-plugins/<kind>/<plugin-id>/`) всегда неявно доступна на
чтение/запись - каждый плагин получает собственную приватную директорию-песочницу бесплатно.
Всё сверх этого требует одного из:

- **Объявленная статическая область** - фиксированный улей реестра+ключ или префикс пути
  файловой системы, который плагину действительно нужен в известном месте (например,
  фиксированные ключи реестра поставщика платформы или фиксированная директория манифестов).
  Объявляется один раз, проверяется хостом при каждом вызове файла/реестра.
- **Область, запрошенная во время выполнения** (`request-read-scope`) - для директории,
  обнаруживаемой только во время выполнения (там, куда установка Steam пользователя фактически
  поместила папки библиотеки). Хост предоставляет это только если распознаёт id плагина *и*
  запрошенный путь проходит реальную структурную проверку для этого поставщика (например,
  требование поддиректории `steamapps`) - нераспознанный id плагина отклоняется сразу, никогда не
  доверяется молча.

В любом случае объявленные манифестом (или показанные при подтверждении установки) области
показываются пользователю перед установкой плагина, так что "к чему это на самом деле может
получить доступ на моём диске" видно заранее, а не только применяется молча.

## Ограничение запуска процессов

`spawn-process`/`run-and-wait` ограничены явным предоставлением возможности `"run-programs"` -
объявление этого плагином в поле `capabilities` его манифеста запускает реальный запрос "этот
плагин запускает другие программы в вашей системе" в UI подтверждения установки, который
пользователь должен явно принять. Хост применяет это ограничение независимо от того, что заявлено
в манифесте (плагин не может просто опустить это поле, чтобы пропустить запрос и всё равно
вызвать функцию) - поле `capabilities` управляет только тем, запрашивает ли UI это разрешение
вообще.

## Ограничение сети

`http-get`/`http-request`/`download-bytes` находятся в allowlist/ограничены по частоте для
каждого плагина, а не являются общим разрешением "может достучаться до всего интернета".

## Чего это *не* решает: доверие, а не только изоляция

Ограничение путей/процессов/сети ограничивает *к чему* может получить доступ плагин, но ничего не
говорит о том, делает ли сам код что-то злонамеренное в пределах этой области (плагину source
действительно нужен `spawn-process` для запуска игр - это не то, что песочница может отличить от
запуска чего-то другого). Эту проблему решают ещё два уровня:

### Подписание кода (рекомендательное)

Опубликованные релизы плагинов могут нести аттестацию [Sigstore](https://www.sigstore.dev/) -
проверяемое доказательство того, какая CI-сборка произвела данный бинарник `.wasm` и из какого
исходного коммита. Это **рекомендательно, а не жёсткий барьер на этапе установки** - Concourse не
отказывается устанавливать неподписанный плагин, поскольку это столь же легко заблокировало бы
автора плагина, который ещё не настроил подписание. Рекомендательная проверка отображается в UI
подтверждения установки и *действительно* применяется жёстко для проверенного реестра ниже.

### Проверенный реестр (жёстко контролируемый)

[`concourse-plugin-registry`](https://github.com/smh0505/concourse-plugin-registry) - это
рецензированный список плагинов с зафиксированными хэшами - каждая запись привязывает манифест/
WASM плагина к точному SHA коммита и хэшу содержимого. Установка через реестр (а не через
произвольно вставленный URL) **жёстко отклоняет при несовпадении хэша** - если то, что фактически
отдаётся, больше не совпадает с тем, что было рецензировано, установка полностью проваливается,
а не предупреждает и продолжает. Удаление записи из реестра *является* механизмом отзыва (только
на этапе установки - он не затрагивает уже установленные копии).

**Короче говоря**: плагины, установленные через реестр, получают реальные, применяемые гарантии
целостности. Плагины, установленные по произвольному URL, получают изоляцию и видимые объявленные
области, но фактическое решение о доверии по-прежнему за вами - см. [Публикация](./publishing),
если вы хотите, чтобы ваш собственный плагин достиг более сильного, рецензированного уровня.
