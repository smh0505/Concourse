# Publishing

## 자유 형식 URL 설치 (항상 가능)

누구나 어디에도 등록되지 않고도 오늘 당장 여러분의 플러그인을 설치할 수 있습니다 - Concourse의
"Add Plugin" 대화상자는 `plugin.json` 매니페스트에 대한 직접 URL을 받습니다. 컴파일된 `.wasm`과
매니페스트를 릴리스 자산으로 담아 GitHub 릴리스를 게시하고, 매니페스트의 릴리스 자산 URL을
공유하면 끝입니다. 이것은 대체 수단이 아니라 실제 1급 설치 경로입니다 - 플러그인 작성자가
설치 가능해지기 위해 어떤 레지스트리에 등록될 필요가 없습니다.

자유 형식 URL을 대상으로도 업데이트 확인이 잘 동작하도록 하려면, 일반적인 방식대로(태그가 붙은
버전, 예: `v0.2.0`) 릴리스를 게시하고 `.../releases/latest/...` 링크가 아니라 해당 태그 자체의
자산 URL을 가리키게 하세요. 그래야 특정 설치가 실제로 설치된 그 시점에 고정된 채로 유지됩니다.

### 코드 서명 (권장)

플러그인 저장소의 CI가 릴리스 아티팩트에 대한 빌드 출처를 증명한다면(예:
[`actions/attest-build-provenance`](https://github.com/actions/attest-build-provenance)),
Concourse는 이를 설치 확인 UI에서 권고성 검증으로 표면화합니다 - 사용자가 설치하려는 `.wasm`이
변조된 사본이 아니라 실제로 여러분 저장소 자체의 CI에서 나왔다는 증거입니다. 필수는 아니지만,
자유 형식 URL 설치가 레지스트리 항목([Security Model](./security-model) 참고)만큼 얻을 수 없는
유일한 것입니다.

## 큐레이션된 레지스트리

[`concourse-plugin-registry`](https://github.com/smh0505/concourse-plugin-registry)는 손수
큐레이션되고 해시로 고정된 목록으로, 설치 시점에 강제 콘텐츠 검증을 받습니다(불일치는 그냥
표시만 되는 것이 아니라 완전히 거부됩니다) - 자유 형식 URL 설치보다 의미 있게 더 강한 보장입니다.
솔직히 말해 이 글을 쓰는 시점 기준으로는, 공개된 커뮤니티 제출 프로세스가 아니라 한 사람
(Concourse와 동일한 유지보수자인 `smh0505`)이 검토한다고 스스로 문서화하고 있습니다 -
"검토됨(reviewed)"은 누군가 그 특정 고정 버전의 소스를 실제로 읽었다는 뜻이며, 이 정책을 먼저
바꾸지 않는 한 임의의 서드파티 풀 리퀘스트를 그대로 받아들이는 방식으로는 확장되지 않습니다.
플러그인이 포함되기를 원한다면, 자신의 항목을 추가하는 PR이 그대로 받아들여질 것이라고 가정하지
말고 해당 저장소에 이슈를 여세요.

### 등록 항목이 실제로 고정하는 것

```json
{
  "id": "your-plugin-id",
  "name": "Your Plugin",
  "kind": "source",
  "repo": "you/your-plugin-repo",
  "manifestUrl": "https://github.com/you/your-plugin-repo/releases/download/v0.2.0/plugin.json",
  "wasmSha256": "<sha256 of the pinned .wasm, computed by the reviewer>"
}
```

`manifestUrl`은 항상 특정한, 변경 불가능한 하나의 릴리스 자산을 가리킵니다 - `.../latest/...`가
아닙니다 - 큐레이션된 항목의 핵심은 오늘 설치되는 것이 다음에 무엇을 게시하든 상관없이 정확히
검토된 그 버전이라는 점이기 때문입니다. `wasmSha256`은 검토자가 실제 릴리스 아티팩트로부터
계산하며, 이 레지스트리를 통한 모든 설치마다 실제로 다운로드된 바이트와 대조 검사됩니다.

### 등록 항목을 최신 상태로 유지하기

플러그인이 실제로 등록되어 있다면, 레지스트리 자체의 CI가(여러분의 릴리스 워크플로가 보내는
`repository_dispatch`를 통해) 새 릴리스를 자동으로 감지하고 레지스트리에 대한 버전 업데이트 PR을
열 수 있습니다 - 누군가 여러분이 업데이트를 배포한 것을 알아채야 하는 대신, 검토를 위해 새
릴리스의 자산을 다시 가져오고, 다시 해시하고, 다시 고정합니다. 그 PR도 최초 등록과 동일한
검토 기준으로 사람의 병합이 필요합니다.
