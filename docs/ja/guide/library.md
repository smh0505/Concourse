# ライブラリとゲーム

## ゲームの追加

**手動で**: 「Add Game」ボタンでタイトルと実行ファイルパス(または`steam://run/<appid>`のような
ランチャーURI - [下記参照](#uri-launches-vs-direct-executables))を入力します。ソースプラグインで
まだカバーされていないものに使用してください。

**ソースプラグイン経由**: ソースプラグインをインストールして有効化した後(Settings → Source)、Settingsの
「Scan Now」ボタンでそのプラグインが認識するすべてのゲームを見つけ、ライブラリに追加します。後で再スキャンすると、
すでにライブラリにあるゲームを重複させることなく、新しくインストールされたゲームだけを取り込みます
(重複排除については下記参照)。

## ゲームの編集

任意のゲームの詳細ページを開き(カバー/タイトルをクリックするか、編集アイコンをクリック)、編集モードに切り替えます。
タイトル、カバー/背景アートワークのURL、説明(Markdown対応)、リリース日、プラットフォームを上書きできます。
「Fetch Metadata」ボタンは、有効化されているメタデータプロバイダ(Settings → Metadata Provider)を現在の
タイトルに対して再実行し、見つかったものを入力します - 自動取得が何かを見逃していた場合や、ゲームを最初に
追加した後にプロバイダのデータが変わった場合に便利です。

## タグとコレクション

- **タグ**は自由形式のラベル(「Co-op」「Backlog」「Completed」)です - Tagsサイドバータブから作成/名前変更/削除し、
  各ゲームの詳細ページから個別に割り当てます。
- **コレクション**はシリーズ/フランチャイズをグループ化します(「Final Fantasy」) - タグとは異なる概念で、
  同様に専用のサイドバータブから管理します。

## 検索、フィルタリング、並べ替え

検索バーは通常のタイトルテキストに加えて3つの特殊なトークンを受け付け、すべて1つのクエリ内で組み合わせられます:
`platform:steam`、`tag:coop`、`collection:"final fantasy"`(スペースを含む値は引用符で囲みます)。
`platform:steam zelda` と入力すると、Steamのゲームの中でのみタイトルから「zelda」を検索します。

検索バーの下には、同じプラットフォーム/タグ/コレクションを反映したクリック可能なピルが表示されます - いずれかを
クリックすると、そのトークンが検索ボックスに追加または削除され、検索バーとピルは常に一致します。同じ種類の複数の
ピルは、**OR**(選択したいずれかの値に一致 - デフォルト)または**AND**(選択したすべての値に一致する必要がある)の
いずれかで組み合わされます。カテゴリがどちらを使用するかは「browse all filters」ピルから切り替えます(行の表示数には
上限があり、そのピルをクリックするとプラットフォーム/タグ/コレクションごとにグループ化された、上限なしのすべての
一覧を示すモーダルが開きます)。ソースプラグインのプラットフォームなしで手動追加されたゲームは、`manual`
プラットフォームのピルの下に表示されます。

表示モード切り替えの隣にある個別の並べ替えドロップダウンでは、タイトル(A-Z)、最近プレイした、最もプレイした、
最近追加されたを選択できます - この選択はグリッド/リスト表示モードと同様、再起動後も保持されます。

## 一括操作

並べ替えドロップダウンの隣にあるチェックボックス形式のトグルをクリックすると選択モードに入ります: すべての
カード/行がワンクリックで選択できる対象になり、現在選択されている内容を示す小さなチェックボックスバッジが
表示されます。「N件選択中」バーが表示され、全選択(現在アクティブなフィルタ/検索を考慮します)とクリアの
ボタン、さらにタグの追加、コレクションへの追加、選択したものすべてをライブラリから削除するといった一括操作が
利用できます。Xボタンで選択モードを終了すると通常の表示に戻ります。

## ソース間の重複排除 {#deduplication-across-sources}

同じゲームが手動で追加され、後でソースプラグインのスキャンによっても見つかった場合(または2つの異なる
ソースプラグインで見つかった場合)、Concourseは重複を表示するのではなく、タイトルで一致させて1つのエントリに
統合します。複数のソースが同じタイトルを見つけた場合、Sourceタブの優先順位でより後ろにあるプラグインが
起動パス/プラットフォームで優先されます(別のプラグインを優先させたい場合は、そこでプラグインの順序を
入れ替えてください)。

同じタイトルの2つのエントリを本当に別々に保ちたい場合(例えば同じゲームの2つの異なるバージョン)、ゲームの
編集フォームに「Keep separate from plugin scans」チェックボックス(`skip_dedup`)があります -
チェックを入れると、その特定のエントリを統合ロジックから除外できます。

## オフライン翻訳 {#offline-translation}

ゲームのタイトルと説明を、完全にオフラインで現在のUI言語に翻訳できます - 外部の翻訳サービスを使わず、
何もあなたのマシンから外部に送信されません。ゲームの詳細ページから「Translate」ボタンをクリックすると、
3つのグループを持つメニューが開きます(スクロールするか矢印キーでグループ間を移動できます)。

- **Translate** - タイトルのみ、説明のみ、または両方を翻訳します。異なるモデルを選択して再実行すると、
  そのフィールドの以前の翻訳が上書きされます。
- **Show** - 翻訳されたテキストと元のテキストを、フィールドごとまたは両方まとめて切り替えます。この選択は
  ゲームごとに記憶されるため、後でゲームを開き直すと最後に選択した表示方法が表示されます。
- **Remove** - フィールド(または両方)のキャッシュされた翻訳をクリアし、何もキャッシュされていない
  元のテキストに戻します。

**初回セットアップ**(Settings): 翻訳エンジンを一度だけダウンロードし(小さな、一度きりのダウンロード)、
ドロップダウンからモデルを選んでそれもダウンロードします。サイズ/RAMと品質のトレードオフとなるいくつかの
モデル階層が用意されており、すべてCPU上で完結して動作するため、小さい階層ほど翻訳が速くメモリ使用量も
少なくなり、ゲームをプレイしながら並行して動かせます。1つの階層は無検閲で、安全性チューニングされたモデルが
正当なサードパーティ製テキストの翻訳を拒否することなく、NSFWゲーム自体の説明文を翻訳することを目的として
います。

キャッシュされた翻訳は、それが作成されたUI言語に紐付いています - UI言語を切り替えたり、ゲームの元のタイトル/
説明を編集したりすると自動的に無効化されます(新しい言語や編集後のテキストで最新の翻訳を得るには再度翻訳
してください)。

## URI起動と直接実行ファイルの違い {#uri-launches-vs-direct-executables}

一部のソースプラグイン(Steam、Epic)は、直接`.exe`パスではなくプラットフォームのURI(`steam://run/...`、
`com.epicgames.launcher://...`)経由でゲームを起動します。これはプラットフォーム自身がゲーム起動の指示を
受け取る方法だからです。プレイ時間の追跡はこれらの場合異なる動作をします -
下記の[プレイ時間の追跡](#playtime-tracking)を参照してください。

## プレイ時間の追跡 {#playtime-tracking}

直接実行ファイルパスの場合、Concourseは実際のプロセスを待機し、プロセス終了時に実際のセッション
(開始/終了/所要時間)を記録します。URI起動されたゲームの場合、同じ方法で待機できるプロセスハンドルが
存在しないため、セッションは同じようには記録されません - Statsタブの「Recently Played」/総プレイ時間の
数値は、起動方法ごとに実際に追跡可能な内容を反映します。
