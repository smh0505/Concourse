# マニフェストリファレンス

組み込みTypeScript、WASM、データのみのテーマを問わず、すべてのプラグインは`plugin.json`マニフェストで
記述されます。このページでは、Concourseのローダーが理解するすべてのフィールドを文書化します
(ソース: `src/plugins/manifest.ts`の`PluginManifest`インターフェース)。

## コアフィールド(すべてのプラグイン共通)

| フィールド | 型 | 必須 | 補足 |
|---|---|---|---|
| `id` | `string` | はい | 一意な識別子。WASMプラグインのインストールディレクトリ名として使われるので、ファイルシステムセーフに保ってください。 |
| `name` | `string` | はい | Settingsに表示される表示名。 |
| `version` | `string` | はい | アプリ自身のバージョンとは独立した、通常のSemVer。詳細は下記の[バージョニング](#versioning)を参照。 |
| `kind` | `"source" \| "theme" \| "metadata" \| "controller" \| "wrapper"` | はい | このプラグインが提供する機能 - エントリのモジュール/コンポーネントが何をエクスポートすべきかを決定します。 |
| `entry` | `string` | はい | コンパイル済みの`.wasm`ファイルへのパス。プラグイン自身のフォルダからの相対パス。 |
| `runtime` | `"wasm" \| "data"` | いいえ | WASMプラグインの場合は`"wasm"`、コード不要のテーママニフェストの場合は`"data"`を設定します(読み込むべき`entry`が一切なく、`cssVariables`がプラグインそのものです)。サードパーティのマニフェストは常にこの2つのどちらかを設定すべきです。(`"ts"`/未指定はローダーが認識する3つ目の値ですが、これはビルド時にアプリ自体に組み込まれるTypeScriptモジュールを意味します - 内部専用であり、配布するマニフェストで設定することは決してありません。) |
| `installable` | `boolean` | いいえ | このプラグインがインストール/アンインストールのライフサイクル(`install()`/`uninstall()`/`isInstalled()`)を実装している場合はtrue - 汎用の「Install」ボタンUIが自動的に表示されるかどうかを決定します。 |

テーママニフェストには独自の専用フィールドセット(`cssVariables`/`cardVisual`/`fontFaces`)があります -
これらについてはこのページではなく[テーママニフェスト](./theme-manifests)を参照してください。

## WASMプラグインのフィールド

| フィールド | 型 | 補足 |
|---|---|---|
| `settingsSchema` | `{ key, label, type? }`の配列 | ユーザーが設定可能な項目(APIキーなど)を宣言します - プラグイン独自のカスタム設定UIを必要とせず、ホストがこれから1つの汎用設定フォームをレンダリングします。`type: "password"`は入力をマスクします。 |
| `capabilities` | `string[]` | このプラグインが実際に呼び出す、ゲート付きのホスト機能。現時点では`"run-programs"`のみ(`spawn-process`/`run-and-wait`をゲートします) - 詳細は[セキュリティモデル](./security-model)参照。ホストはここで何が宣言されていようと無関係にゲートを強制します。このフィールドはインストール確認UIがユーザーに明示的な許可を求めるかどうかだけを決定します。 |

`pathScopes`/`httpScopes`(自分のプラグインディレクトリを超えた宣言済み読み取りアクセスと、許可された
ネットワークホスト)は、ユーザーへの可視性のためインストール確認ダイアログに表示されますが、
`plugin.json`で直接宣言するのではなく、プラグインの実際のWITレベルのリクエストからホストが計算します -
実際のスコーピングの仕組みについては[セキュリティモデル](./security-model)を参照してください。

## ホストが追加するフィールド(自分で設定してはいけません)

| フィールド | 型 | 補足 |
|---|---|---|
| `sourceUrl` | `string` | これがインストールされた正確なURL - 後のアップデートチェックが再取得してバージョンを比較できるよう、インストール時にホストが追加します。 |
| `installedViaRegistry` | `boolean` | 自由形式で貼り付けられたURLではなく、キュレーションされたレジストリのハッシュ固定エントリ経由でインストールされた場合はtrue - アップデートチェックの仕組みが変わります(レジストリで固定された`sourceUrl`はコミットSHAで固定され永久に変わりません。アップデートの確認は`sourceUrl`を再取得するのではなく、このidに対するレジストリの*現在の*エントリを再取得することを意味します)。 |

## 例: 最小限のソースプラグインマニフェスト

```json
{
  "id": "my-scanner-plugin",
  "name": "My Scanner Plugin",
  "version": "0.1.0",
  "kind": "source",
  "entry": "my_scanner_plugin.wasm"
}
```

テーママニフェストの例については[テーママニフェスト](./theme-manifests)を参照してください。

## バージョニング {#versioning}

プラグインのバージョンは、アプリ自身のバージョンとは独立して追跡される通常のSemVerです。

- **パッチ**: マニフェスト/動作の変更を伴わないバグ修正。
- **マイナー**: 後方互換性のある新機能 - 同じホストWITインターフェース(WASMプラグイン)または
  `PluginBase`の形状(TSプラグイン)に対して引き続き動作します。
- **メジャー**: 破壊的変更 - マニフェストの形状が変わる、または(WASMプラグインの場合)古いConcourse
  ビルドが持っていない`wit/plugin.wit`インターフェースバージョンをプラグインが必要とするようになる。
  これは「このプラグインを古いアプリビルドにインストールしないでください」という合図です。

個別にインストールされるWASMプラグインとデータのみのテーママニフェストは、慣例的にそれぞれ`0.1.0`/
`1.0.0`から始まります - コンテンツのみのテーママニフェストは`1.0.0`から始めるのに十分安定していますが、
実際のインストール/起動ロジックを持つWASMプラグインは通常、実運用で実証されるまで`0.1.0`から始まります。
