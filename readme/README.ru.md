*Этот перевод выполнен машинным способом (тот же подход, что и для языков интерфейса самого
приложения - см. [Localization](#возможности) ниже), пока не проверен носителями языка.*

Настольное приложение, объединяющее игры из нескольких источников (Steam, Epic, GOG, Xbox, EA
app, Ubisoft Connect, вручную добавленные игры и многое другое через плагины) в единую
библиотеку, с консольным режимом "Big Picture", ориентированным прежде всего на геймпад - по
духу похоже на Playnite или собственную библиотеку Steam.

Основное приложение остаётся лёгким; почти всё, что выходит за рамки базовой библиотеки
(сканеры источников, темы, поставщики метаданных, раскладки контроллера, обёртки
совместимости), реализовано в виде плагинов.

## Возможности

- **Ядро библиотеки** - ручное «добавление игры», хранение на основе SQLite, вид сеткой и
  списком, теги, поиск/фильтрация
- **Метаданные и медиа** - обложка через SteamGridDB, описание/жанр/дата выхода через IGDB,
  ручное переопределение
- **Запуск и учёт времени игры** - единый запуск независимо от источника (прямой exe, URI
  Steam `steam://`, обработчики протоколов Epic/GOG, игры, запускаемые через обёртку
  совместимости), с учётом времени игры на основе завершения процесса или папки, в
  зависимости от того, как была запущена игра
- **Режим Big Picture** - полноэкранный интерфейс с навигацией геймпадом, с сеткой плиток и
  слайд-шоу в стиле coverflow, плавным переходом фонового изображения, переключателем
  автозапуска при загрузке
- **Обёртки совместимости** - профили Locale Remulator / Locale Emulator для отдельных игр,
  которым для работы требуется нестандартный язык/регион
- **Система плагинов** - пять типов плагинов (источник, тема, поставщик метаданных,
  раскладка контроллера, обёртка совместимости), загружаемых либо во время сборки
  (встроенные TypeScript-плагины в `src/plugins/`), либо во время выполнения (загружаемые
  WebAssembly-плагины - см. ниже)
- **Локализация** - интерфейс доступен на 10 языках (английский плюс 9 машинно переведённых
  локалей), настраиваемый темой `--font-family` для полного изменения оформления приложения,
  а также уровень тем только на данных (`cssVariables` + необязательное переопределение
  `cardVisual` в формате JSON-AST для области обложки, без необходимости в коде)
- **Офлайн-перевод** - название/описание игры можно перевести на текущий язык интерфейса
  полностью на устройстве (без внешнего сервиса): один раз скачайте готовый серверный бинарник
  llama.cpp, выберите модель (несколько уровней, дружелюбных к CPU, и один нецензурированный
  уровень для описаний NSFW-игр), а затем переводите/переключайте отображение/отменяйте
  название и содержимое независимо друг от друга со страницы сведений об игре. Переводы
  сохраняются для каждой игры и каждого поля отдельно и автоматически становятся
  недействительными при смене языка или редактировании оригинала
- **Автообновление** - и само приложение, и каждый установленный плагин/тема автоматически
  проверяют и применяют обновления

## Технологический стек

- **Tauri 2** (бэкенд на Rust) + фронтенд **Vue 3** (`<script setup>`, TypeScript)
- **SQLite** через `tauri-plugin-sql`, схема развивается через версионированные миграции
- **Pinia** для состояния фронтенда, один store на каждый домен
- **wasmtime** (Wasm Component Model) для системы плагинов, загружаемых во время выполнения

## Разработка

Этот репозиторий использует [`bun`](https://bun.sh), а не npm/yarn/pnpm.

```sh
bun install          # установить JS-зависимости
bun run dev           # только dev-сервер Vite (фронтенд)
bunx tauri dev         # полное приложение (фронтенд + бэкенд Rust), с горячей перезагрузкой
bunx tauri build        # production-сборка десктопного бинарника
```

Из `src-tauri/`: `cargo check` для быстрой проверки компиляции Rust без полной сборки.

## Архитектура плагинов

У каждого плагина есть манифест `plugin.json` (`{ id, name, version, kind, entry }`), и он
реализует один из пяти интерфейсов в зависимости от `kind`:

- `source` - `scan()` / `launch()` / `getInstallStatus()`, для интеграций с источниками игр
  (можно включить несколько одновременно)
- `theme` - CSS-переменные (цвета, шрифты, границы/радиусы) плюс необязательное
  переопределение `cardVisual` в JSON-AST для области обложки (активна только одна);
  манифест, содержащий только `cssVariables`, вообще не требует кода. Переопределения
  component-слотов (замена целого пользовательского Vue-компонента) поддерживались на раннем
  этапе, но были упразднены в пользу этого уровня AST с закрытым словарём - для темы не
  существует пути к eval/исполняемому коду
- `metadata` - `fetchMetadata(title)`, для поставщиков обложки / описания / жанра (можно
  включить несколько одновременно)
- `controller` - `GamepadMapping` (индексы кнопок/осей) для конкретной физической раскладки
  контроллера (активна только одна)
- `wrapper` - обёртки совместимости (например, Locale Remulator/Emulator), которые сами
  управляют своей установкой и запускают целевой исполняемый файл через языковой профиль

Плагины времени сборки находятся в `src/plugins/<id>/` и обнаруживаются через
`import.meta.glob` Vite. Плагины времени выполнения - это WebAssembly-компоненты (типы
`source`/`wrapper`/`metadata`), устанавливаемые по URL манифеста (Настройки → соответствующая
вкладка → Добавить плагин) или загружаемые/распаковываемые вручную в каталог данных
приложения, загружаемые через хост `wasmtime`, встроенный в бэкенд на Rust. Темы только на
данных (только `cssVariables`, без кода) - это отдельный, не требующий кода уровень установки
по URL, вообще не нуждающийся в песочнице WASM.

### Официальные плагины

Полный список (ссылки на репозитории, ссылки на скачивание последней версии, инструкции по
установке) смотрите в разделе
**[Official Plugins](https://smh0505.github.io/Concourse/guide/official-plugins)** на сайте
документации.

**Примечание по безопасности (Milestone 12, завершено):** песочница Component Model от
wasmtime гарантирует безопасность памяти (плагин не может повредить память хоста или выйти за
пределы собственного выполнения), и теперь каждая функция хоста, доступная плагинам и способная
нанести реальный ущерб, находится под контролем разрешений:
- Для `spawn-process`/`run-and-wait` требуется явное, видимое разрешение для конкретного
  плагина - плагин должен объявить `capabilities: ["run-programs"]` в своём манифесте, и
  приложение отказывается запускать что-либо от его имени, пока вы действительно не дадите
  разрешение (флажок в диалоге подтверждения установки при установке по URL, либо строка
  «Требуется разрешение» с кнопкой «Предоставить» в Настройках для уже установленного
  плагина).
- `write-file`/`remove-dir` строго и безусловно ограничены собственным каталогом плагина, без
  исключений. `read-file`/`list-dir`/`path-exists`/доступ к реестру ограничены белым списком,
  объявленным в манифесте (`pathScopes`), а также, для единственного плагина, чьё место
  установки действительно невозможно узнать заранее (Steam) - проверенным запросом области
  во время выполнения: хост проверяет реальную структурную сигнатуру (подкаталог
  `steamapps`) перед предоставлением доступа и полностью отклоняет любой id плагина, для
  которого у него нет валидатора.
- `http-get`/`http-request`/`download-bytes` ограничены белым списком имён хостов,
  объявленным в манифесте (`httpScopes`) - плагин может обращаться только к тем хостам,
  которые он объявил (точное совпадение или поддомен), а не к произвольному URL,
  контролируемому злоумышленником.

Тем не менее устанавливайте только плагины из источников, которым вы полностью доверяете -
это закрывает проблему «плагин может незаметно достучаться до любой точки вашей системы или
сети», но не является полноценной моделью доверия уровня магазина приложений.

**Модель доверия (Milestone 13, завершено):** два взаимодополняющих, независимых уровня.
- **Подпись** - каждый официальный релиз плагина подписывается аттестацией происхождения
  сборки [Sigstore](https://www.sigstore.dev/), привязывающей опубликованный `.wasm` к
  точному коммиту и запуску CI, который его собрал. Concourse проверяет это при установке и
  показывает результат - **только для информации, не жёсткий барьер**. Это подтверждает, что
  артефакт действительно происходит из собственного CI этого репозитория и с тех пор не
  изменялся (позволяет обнаружить подделку, скомпрометированный токен релиза, взломанный
  репозиторий, подсунувший вредоносную сборку) - но **не** ручается за намерения автора
  репозитория. Код злонамеренного автора тоже получит совершенно валидную подпись, поскольку
  его собственный CI действительно собрал и подписал именно то, что он сам закоммитил.
- **Курируемый реестр** -
  [`concourse-plugin-registry`](https://github.com/smh0505/concourse-plugin-registry),
  вручную поддерживаемый список плагинов, чья зафиксированная версия была реально прочитана,
  каждая запись привязана к конкретному релизу и его настоящему SHA256. Диалог «Добавить
  плагин» показывает эти записи рядом с полем свободного ввода URL; установка из реестра при
  несовпадении хеша приводит к **жёсткому отказу**, в отличие от информативной проверки
  подписи - этот хеш был выбран вручную после проверки, поэтому несовпадение - это реальный
  сигнал «это не то, что было проверено». Удаление записи из реестра *является* отзывом для
  будущих установок (пока не задним числом для уже установленных копий). Установка по
  свободному URL в любом случае продолжает работать точно так же, как и раньше - реестр
  представляет собой дополнительный, более доверенный путь, а не обязательный барьер.

### Уведомления о стороннем ПО

Собственный исходный код Concourse лицензирован по MIT; в репозитории или собранном бинарнике
не содержится ничего стороннего. Функция офлайн-перевода (Milestone 20) загружает два вида
стороннего контента непосредственно на ваш компьютер во время выполнения, каждый на своих
собственных, отдельных условиях - это описано здесь для прозрачности, а не потому, что
Concourse что-либо из этого распространяет:

- **[llama.cpp](https://github.com/ggml-org/llama.cpp)** (MIT) - сам движок перевода.
  Concourse скачивает официальный готовый релизный бинарник для Windows с GitHub и запускает
  его как подпроцесс; никакой код llama.cpp не компилируется в Concourse и не поставляется
  вместе с ним.
- **Веса моделей**, загружаемые с Hugging Face по вашему собственному выбору в Настройках,
  каждая под лицензией собственной карточки модели -
  `qwen2.5-1.5b`/`qwen3-4b`/`gemma4-e2b` все под лицензией Apache 2.0 (Gemma 4 в апреле 2026
  года специально перешла на Apache 2.0, заменив более ограничительную лицензию, под которой
  распространялись более ранние поколения Gemma). Два нецензурированных уровня
  (`qwen3-4b-abliterated`, `gemma4-e2b-abliterated`) наследуют лицензию своей базовой модели;
  перед коммерческим использованием проверьте карточку модели каждой из них на Hugging Face.
